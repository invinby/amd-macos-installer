# Архив: AMD macOS Installer

## О чём проект

Это частный исследовательский проект про совместимость macOS с AMD-железом, начиная с ASUS ROG Strix G513RM. Владелец хотел сразу целиться в macOS 27, но проверка Apple показала жёсткое ограничение: macOS 27 работает только на Apple Silicon; Ryzen 7 6800H — другой тип процессора, x86-64. Поэтому macOS 27 на этом ноутбуке — No-Go для обычного Hackintosh. Полный разбор — в [`docs/research/macos-27-target-check.md`](docs/research/macos-27-target-check.md).

Для ветки G513RM рекомендую macOS Tahoe 26.7.1 — самый свежий выпуск macOS 26 на 22 октября 2026 года. Сначала всё равно проверяем, подходят ли AMD-патчи к её точной сборке; загрузка на Ryzen и ускорение встроенной Radeon 680M не гарантированы. macOS 27 можно изучать отдельно на Apple Silicon, но это не проверит нашу 680M.

Мы не обещаем установку «одной кнопкой», поддержку всех AMD-ноутбуков или готовый драйвер для Radeon 680M.

## Как объяснить проект человеку

> Я исследую совместимость macOS с AMD-ноутбуками на примере ASUS ROG Strix G513RM. Сначала выяснил важное ограничение: macOS 27 рассчитана на Apple Silicon, а мой Ryzen — x86-64, поэтому поставить её на этот ноутбук обычным способом нельзя. Теперь отдельно собираю факты о Radeon 680M и рассматриваю только совместимую с x86 версию macOS для проверки ноутбука. Готового драйвера и ускорения пока нет.

Если спросят, чем ты занимаешься лично: с помощью ИИ исследуешь совместимость операционных систем и железа, проверяешь готовые инструменты и собираешь доказательства по каждому этапу. Отдельная техническая задача — выяснить, можно ли написать драйвер, который даст macOS управлять Radeon 680M. Сам драйвер пока не написан; версия 27 на Ryzen не является достижимой целью.

## Что уже известно

- Ноутбук: ASUS ROG Strix G513RM, AMD Ryzen 7 6800H, Radeon 680M и NVIDIA RTX 3060 Laptop.
- В QEMU 11.1.0 виден экран восстановления macOS Monterey. Текущий выделенный пункт — Safari; надёжное управление этим экраном пока не подтверждено.
- Установка macOS ещё не завершена, рабочего стола Monterey пока нет.
- Виртуальная машина сейчас исполняет процессор программно, поэтому работает медленно. Она показывает macOS виртуальный видеоадаптер, а не настоящую Radeon 680M или RTX 3060.
- Для этой конфигурации пока не найден подтверждённый готовый путь к аппаратному ускорению Radeon 680M. RTX 3060 не считается запасным вариантом.
- Подробности исследований и следующие проверяемые шаги находятся в [`docs/PLAN.md`](docs/PLAN.md) и [`docs/research/`](docs/research/).

## Как поймём, что получилось

Результаты отмечаем отдельно, чтобы не назвать Recovery «готовой macOS»:

1. **Recovery работает** — видим меню восстановления macOS.
2. **macOS установлена** — установщик завершился на виртуальный диск.
3. **macOS загружается** — после перезапуска открывается рабочий стол.
4. **Ноутбук работает с macOS** — проверены экран, клавиатура, звук, сеть, сон и другие устройства.
5. **Есть ускорение графики** — macOS действительно использует поддерживаемый видеодрайвер и аппаратное ускорение; это подтверждено проверкой, а не только красивым изображением на экране.
6. **Можно повторить** — другой человек получает те же проверенные шаги, понятные сообщения об ошибках и путь отката.

Только последняя ступень вместе с нужными проверками железа позволит честно говорить о пригодном способе установки. Успех в виртуальной машине сам по себе не подтверждает работу видеокарты ноутбука.

## План простыми словами

1. Зафиксировать, что macOS 27 не запускается на процессоре Ryzen этого ноутбука; для G513RM выбрать актуальную macOS Tahoe 26.7.1 как исследовательскую цель.
2. Собрать сведения о Radeon 680M безопасным способом из Linux, пока только читая данные.
3. Если нужна именно macOS 27 — изучать её отдельно на Apple Silicon. Для проверки G513RM сначала проверить Ryzen-патчи под Tahoe 26.7.1.
4. Понять, есть ли законный и технический путь к драйверу 680M для выбранной версии macOS.
5. Писать первый код только после этого: сначала программа должна лишь обнаружить видеокарту и записать сведения, без опасного управления железом.
6. Проверять изображение, ускорение и Metal как разные ступени. Не менять внутренний диск Windows до отдельного плана восстановления.
7. Упаковать установщик только после того, как шаги действительно повторятся на целевом ноутбуке.

## Когда начнём писать драйвер

macOS 27 на нашем Ryzen не запускается из-за несовпадения архитектуры процессора и системы. Поэтому драйвер для 680M нельзя начинать с обещанием поддержки macOS 27 на этом ноутбуке. Если выберем старую x86-совместимую macOS, сначала соберём паспорт видеокарты: точный PCI ID, путь подключения, версию BIOS и сведения Linux. Эти данные показывают, с каким именно чипом и его прошивками придётся иметь дело.

Драйвер — системная программа-посредник: она объясняет macOS, как находить видеокарту, управлять её памятью, показывать изображение и выполнять графические команды. Для аппаратного ускорения этого недостаточно: GPU должен реально выполнять задачи, а Metal — Apple-интерфейс для графических вычислений — должен подтвердить работу именно на 680M. Первый прототип, если до него дойдём, только распознаёт карту и пишет безопасные сведения в лог. Он не должен сразу менять регистры видеокарты или прошивать BIOS.

Сейчас у нас нет доказательства, что Radeon 680M сможет получить ускорение в macOS. Установка Monterey в виртуалку проверяет только запуск системы на виртуальных устройствах. Она не тестирует macOS 27 и не показывает, что работает видеокарта ноутбука.

## Важные границы

- Репозиторий остаётся приватным, пока владелец явно не решит открыть его.
- Сначала используем готовые компоненты и доказываем, что каждый этап работает.
- Не выдаём запуск Recovery за установленную ОС, а картинку на экране — за аппаратное ускорение.
- Не трогаем раздел Windows без копии важных данных, отдельного плана восстановления и тестового носителя.
- Не кладём в Git образы macOS, личные ключи, пароли и файлы, которые нельзя распространять.
