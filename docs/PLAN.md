# Проектный план

## Цель

Проверить, можно ли на базе готовых открытых компонентов собрать воспроизводимый путь запуска macOS на AMD ноутбуках. Начинаем с ASUS ROG Strix G513RM и сначала проверяем процесс в виртуальной машине. Если VM-этап проходит, отдельно готовим и проверяем dual boot на реальном железе.

Это исследовательский проект. Успешная загрузка сама по себе не означает, что ноутбук станет пригоден для ежедневной работы.

## Подход

- Использовать готовые компоненты там, где они подходят: OpenCore, AMD kernel patches и существующие инструменты сборки/настройки.
- Не считать чужую EFI переносимой только потому, что в ней указан Ryzen 7 6800H. Сначала изучить её структуру, лицензию и отличия железа.
- Не писать собственный графический драйвер на старте. Сначала проверить, что уже существует для Radeon 680M (RDNA 2), и определить, что реально можно подтвердить.
- Не собирать установщик с включёнными компонентами, которые не поддерживают эту конфигурацию.

## Этапы

### 1. Инвентаризация и выбор исходных компонентов

Подтвердить текущие характеристики компьютера и выбранной VM-платформы. Для каждого готового компонента записать назначение, поддерживаемое железо, лицензию, источник и ограничения. Отдельно разобрать ближайший публичный пример EFI для Ryzen 6000 и не копировать его без проверки.

**Результат:** список компонентов и решений с пометками «подходит», «только для изучения» или «не подходит».

### 2. Проверка загрузки в VM

Собрать минимальную конфигурацию из выбранных компонентов и проверить по порядку: OpenCore стартует → установщик macOS стартует → установка завершается → установленная система загружается повторно. Сохранять конфигурацию и логи каждого шага, чтобы результат можно было повторить.

**Что VM может подтвердить:** что выбранная сборка и загрузочная цепочка работают в конкретной виртуальной среде.

**Чего VM не подтверждает:** работу Radeon 680M и её Metal-ускорение, RTX 3060, встроенного экрана, Wi-Fi/BT, аудио, тачпада, клавиатурных функций, сна, батареи, температуры и энергопотребления. VM показывает гостевой системе виртуальное оборудование, поэтому её успешный запуск не является доказательством совместимости ноутбука.

### 3. Подготовка реального dual boot

Только после VM-этапа составить отдельную инструкцию для конкретного ноутбука: резервная копия Windows и важных данных, проверка схемы дисков и загрузки, план отката, затем отдельный тестовый носитель или отдельный накопитель. Не менять разделы Windows, пока не подготовлены резервная копия и проверенный путь восстановления.

**Результат:** решение «переходим к железу / сначала закрываем блокер / останавливаем эксперимент» с понятными критериями.

### 4. Испытания на ноутбуке

Проверять отдельными ступенями: загрузка → установщик → установка → базовые устройства → графическое ускорение → сон/пробуждение → стабильность и пригодность к повседневной работе. Для каждой функции фиксировать подтверждённый результат, способ проверки и известные проблемы.

## Критерии успеха

VM-успех — только воспроизводимый запуск установленной системы в выбранной VM. Он разрешает перейти к планированию проверки на железе, но не означает автоматического разрешения считать macOS рабочей на ноутбуке.

Успех на ноутбуке оценивается отдельно. Ключевой технический вопрос проекта — существует ли пригодная поддержка Radeon 680M с аппаратным ускорением; без неё обычный запуск может быть медленным и непригодным для ежедневной работы.

## Ограничения и открытые вопросы

- Точная совместимость зависит от версии macOS, гипервизора, его настроек и текущих версий загрузчика/патчей; это надо перепроверить перед VM-экспериментом.
- AMD laptop CPU и Radeon 680M — отдельные задачи совместимости. Поддержка процессорных патчей не создаёт графический драйвер.
- RTX 3060 Laptop не рассматривается как резервный macOS GPU.
- До копирования, упаковки или распространения сторонних EFI, kext и системных файлов проверяются лицензии и условия распространения.
- В опубликованном проекте не размещать файлы macOS; пользователь получает их отдельно из допустимого источника.

## Что делаем следующим

Сначала подробно разбираем компоненты и выбираем VM-платформу для компьютера пользователя. После этого фиксируем точный, обратимый VM-эксперимент и его критерии. К реальной установке переходим только после документированного результата VM-этапа и отдельной проверки аппаратных ограничений.
