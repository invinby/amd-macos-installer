# Проверка цели macOS 27 для ноутбука G513RM

Проверено 22 октября 2026 года по документации Apple и AMD.

## Короткий ответ

**macOS 27 нельзя запустить на ASUS ROG Strix G513RM обычным путём Hackintosh/OpenCore.** В ноутбуке стоит AMD Ryzen 7 6800H с архитектурой x86-64. Apple указывает, что macOS 26 — последняя версия для компьютеров Intel, а macOS 27 рассчитана только на компьютеры Apple с Apple Silicon. Процессор Ryzen не становится Apple Silicon от патча или драйвера.

Это стоп именно для сочетания **«macOS 27 на G513RM»**. Он не доказывает, что Radeon 680M никогда не удастся исследовать для более старой x86-версии macOS, и не означает, что в виртуальной машине появился путь к реальной графике ноутбука.

## Почему драйвер не решит это ограничение

- **Архитектура процессора** — набор машинных команд, который выполняет процессор. Ryzen 7 6800H использует x86-64; macOS 27 рассчитана на Apple Silicon с ARM64.
- **Патчи AMD для ядра** меняют отдельные предположения ядра macOS на совместимом x86-64 поколении. Они не переводят весь процессор и ядро операционной системы с x86-64 на ARM64.
- **Rosetta** переводит отдельные программы Intel для запуска на Apple Silicon. Это не средство запуска macOS 27 на Ryzen.
- **Драйвер GPU** объясняет системе, как найти видеокарту и управлять её памятью, экраном и графическими командами. Он не меняет процессорную архитектуру ОС.

Значит, писать драйвер Radeon 680M именно для установки macOS 27 на этот Ryzen сейчас нельзя считать рабочим техническим планом: целевая система на этом процессоре не запускается.

## Развилки проекта

| Путь | Что реально проверяем | Связь с G513RM и Radeon 680M |
|---|---|---|
| macOS 27 на Apple Silicon | Работу системы или своего инструмента в поддерживаемой ARM-среде | Не проверяет Ryzen и не даёт прямого теста 680M в ноутбуке |
| G513RM с macOS Tahoe 26.7.1 (x86-64) | Неофициальный запуск последней актуальной ветки macOS для Intel и отдельную совместимость графики | Единственная ветка, которая может непосредственно проверить CPU и 680M этого ноутбука; Ryzen-патчи для конкретной сборки и ускорение 680M ещё надо подтвердить |
| Сначала только исследование 680M | Linux `amdgpu`, PCI/ACPI, подключение экранов и публичная документация | Без установки macOS и без изменений внутреннего диска; не доказывает поддержку Metal |

**Рекомендация для ветки G513RM — macOS Tahoe 26.7.1**, а не 26.0: это самый свежий выпуск ветки 26 по текущей странице обновлений Apple. В upstream AMD_Vanilla перечислена поддержка Tahoe 26 для AMD CPU, но это не доказывает работу конкретной сборки 26.7.1 на Ryzen 7 6800H и тем более не добавляет драйвер Radeon 680M. Перед подготовкой VM нужно сверить точный номер сборки и применимость CPU-патчей.

План сохраняет пожелание изучить macOS 27 отдельно на Apple Silicon, но не называет её целью установки на Ryzen. Драйверную ветку G513RM планируем для macOS 26.7.1 только после проверки патчей; ускорение 680M остаётся отдельной неизвестностью.

## Что можно делать прямо сейчас

1. Сохранить собранный отчёт Windows о PCI ID Radeon 680M и сверить его с Linux Live USB. В репозитории подготовлен сборщик [`tools/collect-linux-gpu-inventory.sh`](../../tools/collect-linux-gpu-inventory.sh): он только читает сведения об устройстве, драйвере `amdgpu`, названиях прошивок, ошибках и экранных выходах. Единственная запись — новый текстовый отчёт в указанном пользователем месте; внутренний диск и настройки загрузки не меняются.
2. Не устанавливать macOS на внутренний диск и не писать в регистры GPU. Linux-сбор — только чтение.
3. Продолжать текущую QEMU Monterey VM только как отдельную проверку загрузчика и установки на виртуальный диск. Она не тестирует macOS 27 и не передаёт гостю Radeon 680M.
4. Перед VM-экспериментом проверить патчи AMD для macOS Tahoe 26.7.1 и точный номер сборки; перед кодом графического драйвера зафиксировать SDK, доступные законные источники и отдельный способ безопасного отката.
5. Если целью остаётся именно 27, сначала обеспечить Apple Silicon среду и сформулировать отдельную задачу. Она не сможет подтвердить работу 680M в G513RM.
